01 / Begin with the question

Why not train and test on the same observations?

Imagine preparing for an examination by memorising last year's answers. You might score 100% when the same questions reappear. But that does not tell us how well you understand new questions. Machine-learning models face exactly this problem.

Random split

Every observation is shuffled into a set without explicitly preserving class proportions. Rare classes can be unevenly distributed, especially in small datasets.

Stratified split

Split each label so each subset approximately matches the original class proportions. This is often useful for imbalanced classification, but does not solve dependencies between related records.

03 / More reliable model selection

K-Fold cross-validation: every example gets a turn

A single validation split can be unrepresentative. K-fold cross-validation repeatedly divides the training pool into K parts: fit on K−1 parts and validate on the remaining part. Rotate the held-out part and average the scores.

CV score = (score1 + score2 + … + scoreK) / KEach score comes from a model fitted without access to that fold's validation examples. These folds use the training set from the experiment above, not the untouched test set.

04 / The trap that inflates accuracy

Data leakage: when the test already knows the answer

Imagine having four very similar measurements from each person. Each person's label is randomly assigned and cannot be learned from genuinely new people's features. If we randomly split individual measurements, copies of the same person will appear in training and testing. The model can recognise those copies.

Random row split

Repeated records from the same person may appear on both sides.…
Misleadingly high accuracy for the goal of predicting new people

Group-aware split

Each person belongs entirely to training or testing, never both.…
More credible estimate for previously unseen people

In this example, … test observations in the random row split come from subjects already represented during training.

Other common leakage problems

Scaling with statistics from all rows before splitting; selecting features using test labels; allowing future measurements into a time-series predictor; and evaluating repeated observations of the same person as independent unseen cases.

Correct workflow: split → fit preprocessing on training only → apply to validation/test → evaluateFor cross-validation, fit preprocessing separately inside each training fold. Scikit-learn Pipelines make this easier to implement safely.

06 / Predict, test, explain

Five questions to think

Make a prediction before changing any control. Then open the explanation and compare it with what you observed.

Q1 · Why might a 90/5/5 split be unreliable for a small dataset?

The training set is large, but the validation and test subsets could be too small for stable performance estimates, especially for rare classes. There is no universal best ratio.

Q2 · What does stratification preserve, and what does it not fix?

Stratification aims to preserve class proportions. It does not prevent data leakage caused by duplicated subjects, groups, chronological dependencies or preprocessing fitted on the full dataset.

Q3 · Are KNN's K and K-fold's K the same thing?

No. KNN's K is the number of nearest labelled neighbours used for a prediction. K-fold's K is the number of subsets used for repeated training and validation.

Q4 · Why is 100% training accuracy not enough?

A model may simply memorise the training data. Accuracy on observations that were not available during fitting is needed to evaluate generalisation.

Q5 · Can we keep changing K until the final test accuracy is highest?

No. Repeatedly selecting based on the test set makes it part of the model-selection process. Use validation or cross-validation for tuning and keep a final test set untouched.
